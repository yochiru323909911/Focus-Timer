# משימה 14: Focus Timer

קיבלתם דף מוכן של שעון למידה. הוא נראה טוב, אבל הוא קפוא: שום דבר בו לא מגיב.
בכל חלק נוסיף hook אחד, ועוד חלק בדף יתעורר לחיים.

## התחלה

```bash
npm install
npm run dev
```

פתחו את `http://localhost:5180` ואת ה-Console. כל קומפוננטה מדפיסה `render` בכל פעם שריאקט מריצה אותה.

```
App
├── Header
│   └── ThemeButton
├── FocusTimer
└── SessionList
    └── SessionItem
```

הכלל שלנו לאורך השיעור: לפני כל לחיצה מנחשים אילו קומפוננטות יודפסו, ורק אז לוחצים.

---

## חלק 1: useState

**השאלה:** איך ריאקט יודעת שמשהו השתנה וצריך לצייר מחדש?

**קבצים:** `FocusTimer.jsx`, `App.jsx`

### 1.1 הנושא

מה שמקלידים בשדה מופיע מיד אחרי `Now studying:`.

> רמז: השדה צריך גם לקרוא את הערך מה-state וגם לעדכן אותו. אלה שני props שונים על אותו input.

### 1.2 כפתור ההפעלה

לחיצה על `Start` הופכת אותו ל-`Pause`, ולחיצה נוספת מחזירה. השעון עדיין לא זז.

> רמז: לא שומרים את הטקסט של הכפתור. שומרים עובדה אחת, כן או לא, והטקסט נגזר ממנה.

### 1.3 שמירה

הרשימה מתחילה ריקה. לחיצה על `Save session` מוסיפה לה מפגש ומנקה את השדה. כשאין נושא, הכפתור מושבת.

> רמז: מי שמחזיקה את הרשימה ומי שלוחצת על הכפתור הן שתי קומפוננטות שונות. נתונים יורדים ב-props. מה אפשר להוריד כדי שמידע יעלה חזרה?

> רמז: ריאקט משווה בין המערך הישן לחדש. אם זה אותו מערך, מבחינתה לא קרה כלום.

**ניסוי:** החליפו את ה-state של הנושא במשתנה `let` רגיל. המשתנה באמת משתנה. למה המסך לא?

## חלק 2: useEffect

**השאלה:** איפה כותבים קוד שנוגע במשהו מחוץ לריאקט?

**קבצים:** `App.jsx`, `FocusTimer.jsx`

### 2.1 כותרת הלשונית

בלשונית של הדפדפן מופיע מספר המפגשים, למשל `Focus Timer (2)`.

> רמז: הכותרת לא נמצאת בתוך ה-JSX שלנו. מעדכנים אותה אחרי הציור, ורק כשהרשימה השתנתה.

### 2.2 השעון

כשהשעון פועל, הוא עולה באחד בכל שנייה. השמירה שומרת את הזמן ומאפסת אותו.

> רמז: ה-effect תלוי בעובדה אחת בלבד. כשהיא שקרית, אין לו מה לעשות.

> רמז: הפונקציה שרצה כל שנייה נוצרה ברינדור ישן וזוכרת את הערך שהיה אז. איך מעדכנים state לפי הערך העדכני ביותר?

### 2.3 עצירה

לחיצה על `Pause` באמת עוצרת את השעון.

> רמז: מי שפותחת ברז גם סוגרת אותו. effect יכול להחזיר פונקציה, וריאקט תדע מתי לקרוא לה.

**ניסוי:** מחקו את ה-cleanup ולחצו Start, Pause, Start. מה קורה לקצב, ולמה?

**ניסוי:** ב-2.1 נסו שלוש גרסאות: בלי מערך תלויות, עם מערך ריק, ועם הרשימה.

## חלק 3: useRef

**השאלה:** איך זוכרים משהו בין רינדורים בלי לגרום לרינדור?

**קובץ:** `FocusTimer.jsx`

### 3.1 פוקוס

אחרי שמירה הסמן חוזר לשדה הטקסט, ואפשר מיד להקליד נושא חדש.

> רמז: לפעמים צריך את אלמנט ה-DOM עצמו. יש prop מיוחד שמחבר אלמנט ל-ref, והאלמנט מחכה בתוך `current`.

### 3.2 מונה הסחות

כל לחיצה על `Got distracted` נספרת, אבל המסך לא משתנה. המספר נחשף רק ברשימה, אחרי השמירה, והספירה מתחילה מחדש.

> רמז: צריך מקום ששורד רינדור, אבל שינוי שלו לא מעניין את ריאקט. ה-Console צריך להישאר בלי `render` אחרי הלחיצה.

**ניסוי:** החליפו את ה-ref במשתנה `let` בתוך הקומפוננטה, ולחצו כשהשעון רץ. כמה הסחות נשמרו?

## חלק 4: useContext

**השאלה:** איך מעבירים מידע לקומפוננטה רחוקה בלי לעבור דרך כולן?

**קבצים:** `context/ThemeContext.js` (חדש), `App.jsx`, `ThemeButton.jsx`, `SessionItem.jsx`

### 4.1 מקור אחד

ערכת הנושא, `light` או `dark`, נשמרת ב-`App` וזמינה לכל העץ. ה-class של הדף נקבע לפיה.

> רמז: שלושה שלבים: יוצרים, עוטפים, צורכים. כאן עושים את שני הראשונים.

> רמז: אפשר לשתף ערך יחיד, ואפשר לשתף את כל הזוג ש-`useState` מחזיר.

### 4.2 הכפתור

`ThemeButton` מחליף בין בהיר לכהה, והטקסט שלו מתחלף בהתאם. ב-`Header` לא נוגעים.

> רמז: השלב השלישי. שימו לב לסוג הסוגריים בפירוק: הם תלויים במה ששמנו ב-value.

### 4.3 הכרטיסים

גם כל `SessionItem` מתחלף. ב-`SessionList` לא נוגעים.

> רמז: אותו context, צרכן נוסף. ב-class יש כרגע מילה אחת קבועה שצריכה להפוך למשתנה.

**ניסוי:** הסירו את ה-Provider ולחצו על הכפתור. למה אין שגיאה, ומאיפה הגיע הערך?

## סיכום

ענו במשפט אחד:

1. מה גורם לקומפוננטה להתרנדר?
2. מתי state ומתי ref?
3. מתי רץ ה-cleanup של effect?
4. איזו בעיה context פותר, ואיזו הוא לא פותר?

## בונוס

1. **שמירה לאחר רענון:** הרשימה נשמרת ב-`localStorage`. רמז: effect אחד כותב, והקריאה קורית רק פעם אחת, בערך ההתחלתי של ה-state.
2. **בידוד הרינדורים:** העבירו את ערכת הנושא לקומפוננטה `ThemeProvider` שעוטפת את `App`. רמז: `children`. המטרה היא שבהחלפת ערכת נושא יודפסו רק הצרכנים.
3. **מבחן לחץ:** עטפו את `App` ב-`StrictMode`. אם ה-cleanup נכון, השעון ימשיך לעבוד כרגיל.
